# Run — 2026-11-19 — the file writer checks its own output

Bug [rpg-project#1014](https://github.com/KirkDiggler/rpg-project/issues/1014), found in the review of [#1459](https://github.com/KirkDiggler/rpg-dnd5e-web/pull/1459#pullrequestreview-5970549824). Base: `rpg-dnd5e-web` `dev` at [`84789fe2`](https://github.com/KirkDiggler/rpg-dnd5e-web/commit/84789fe2). Branch `splice-guard-1014`, PR [#1460](https://github.com/KirkDiggler/rpg-dnd5e-web/pull/1460), with one review round ([review](https://github.com/KirkDiggler/rpg-dnd5e-web/pull/1460#pullrequestreview-5971273244)).

## Shipped

- **The guard.**
  - `spliceYaml` (`src/concepts/world-building/yamlSplice.ts`) checks its own text before returning it. The text must read back as the file's value with the edit applied (`checkWrite`).
  - If not, the write throws `UnsafeWriteError`, whose message is the studio's sentence: "The studio could not write this change safely, so nothing was changed." followed by where.
  - Anything that goes wrong while writing or checking is that refusal too. This includes an alias whose anchor the write lost and a writer that throws.
- **The edit is refused at the commit.**
  - Every room edit goes through `commitRoomDocument`. It calls `assertSourceWritable` before keeping the edit.
  - A refusal shows the sentence. The document, the saved draft and undo stay as they were.
  - Export and publish use the same guarded splice.
- **The cheap path.** When the edits fall in parts of the file that read on their own, and the write is byte for byte the same elsewhere, only those parts are parsed (`checkLocally`). A part that reads on its own is a block collection that starts its own line, or one `key: scalar` line. Anything else gets the full parse, which decides.
- **Compact lists take every edit.** In a list written `- - 3`, the first row that stays keeps the shared line. A fallback rewrite sets the comments of the rows that stay above the parent row.
- **Emptied collections.** A map or list whose every entry goes is written `{}` or `[]` on its key's line. Before this, an emptied map was written `key:`, which reads as null. `dev` did that silently.
- **New room has no file.** It no longer carries the replaced document's `sourceRef`.
- **The castle probe** walks every list, map and scalar.

## Decided

- **The comparison rule.**
  - Counts: list order, every key, every scalar and its type.
  - Ignored: key order, comments and layout.
  - Because: the engine and the studio read maps by key and lists by position.
  - Known gap: numbers compare as numbers, so `1` and `1.0` are not told apart. The splice never writes that change.
- **The cheap path is only trusted when it passes.** A local mismatch or a shape it cannot read goes to the full check. So the short path can never refuse anything, and never accept more than the full check would.
  - Because: the guard must stay the authority. The short path only makes the common edit cheap.
  - Why it is sound: a part is read on its own only when every line of it stays at or right of its column, so no line can join its parent. A `key: scalar` part must stay one line.
- **The only refusal a commit swallows is the encoder's, before it splices** (a policy form part-way through). Everything after that fails closed.
- **The cost, before and after.** These are measurements on the served castle for a keystroke in a policy text field:

  |                                            | dev    | first head | now   |
  | ------------------------------------------ | ------ | ---------- | ----- |
  | commit check                               | —      | 138 ms     | 33 ms |
  | with the publish panel's encode (file key) | 149 ms | 167 ms     | 58 ms |
  | the same, another key                      | 147 ms | 294 ms     | 65 ms |
  - The parse of the canonical text is gone: the encoder takes the value from the document it built.
  - The other-key miss is cheap now, because it takes the cheap path too.

## Found

- **On `dev`, 33 list writes failed, all in the courtyard's compact paint runs.** Moves inside a run were unparseable, and removing or editing a run's first value gave the wrong value.
- **On `dev`, every emptied block map was written `key:`, which is null.** The first round's guard caught it and refused the edit. That broke New room after an import, and removing the last key of any map. The castle probe walked only lists, so it missed this. It now walks maps and scalars too.
- **A row whose `id` changes in an id-aligned list is a different row.** It is written where the old one stood, so its list's bytes change. That is by design.

## Mistaken

- **I took "the castle probe passes" to mean the writer was sound.** It walked lists only. Every node kind the studio can edit needs probing.
- **The commit test mocked `spliceYaml` and called the guard itself.** Deleting the guard from `spliceYaml` failed no test. The tests now break the writer below the guard, through `spliceInternals`.
- **The compact fallback dropped the comment that made it fire.** Its test checked only the value.
- **The first probe recorded every swap twice.**
