## Shipped

- **Start cells.** The fold places each member at its `joined_at` cell. A late joiner is not drawn until its beat arrives. A member the record never places begins where the draft or the snapshot put it, as before. The timeline reads the same starts.
- **Run identity.** The run's `scene_content` (key, engine, short content hash) shows in Run details, for a live watch and for a saved run. A save copies it into the header as `scene_content`.
- **One comparison line.** The run's `content_hash` is compared with the content hash that the studio's own check returns (`PutDungeon{validate_only}`; the preview now keeps `contentHash`). The comparison is made only under the server's `GetMachineWords().encounter_version`. The line is one of: unchanged, changed, saved from `<key>`, saved under another engine, carries no encounter identity, or could not be checked. The last two lines also carry the snapshot comparison's sentence. A live watch says "changed" once the check of a mid-run edit answers.

## Decided

- **The key mismatch is said before the engine rule.** The key is a fact in the record, not a hash, so a run from another encounter is named as that under any engine.
- **No hash, no comparison.** When the open text does not compile (an `errors` answer drops the hash) or has not been checked yet, the line says the comparison could not be made, and it falls back to the snapshot.
- **No extra call per render.** The hash comes from the preview check that already runs on every edit. The engine release is asked once per client, and only while a run that names its encounter is shown.
- **Saved-run format stays 1.** The header gains an optional field, and older files open as before. The one difference: an old file now shows the line "carries no encounter identity", as the issue asks.
- **The timeline's one-sided role match stays.** New traces qualify both sides and compare as equal strings, but runs saved before item 11 have `hold` next to `hold (duty)`. A strict comparison would mark a change at every repeated hold. Both shapes are tested.

- **Review round (rpg-dnd5e-web#1464).**
  - **The record places everyone once it has `scene_content`.** A reserve, or a joiner the stream has not delivered yet, is drawn only from its `arrived` or `joined_at` step, never at its draft cell. The draft fallback is kept only for records that carry no `scene_content`.
  - **The engine release is re-asked for each comparison.** That means each saved run opened, each watch, each new open hash, and each reconnect. Until the answer comes back, nothing is compared.
  - **Another engine falls back to the snapshot.** The line says the content hash cannot be compared, then gives the snapshot comparison ("By its snapshot, …").
  - **A check in flight is not compared.**
  - **A run whose record names no key fails closed.**

## Found

- `joined_at.cell` is the canvas `spatial.Position` (`GetEntityPosition` at setup, `JoinInput.Cell` on a join). `moved.position` is the same type, so the cell needs no conversion of its own.
- `scene_content.key`, `content_hash` and `engine` are each written only when known. The fold treats a run without a `content_hash` as carrying no identity.
- At the time of this run, `useMachineWords` (rpg-dnd5e-web#1462) had not merged. So `useEngineVersion` asks `GetMachineWords` itself. Once both are on `dev`, it can read that hook's answer instead.

## Mistaken

- I first kept the draft fallback per member, so in a new record a reserve was drawn at its draft cell from step 0. The record can only be authoritative for everyone: `scene_content` is the sign that it is.
- I first cached the engine release for the page's whole life. An api re-upped under an open tab would then have had two engines' hashes compared as if they matched.
- I first dropped the snapshot comparison under "another engine". Engine releases land daily, so that lost what saved runs could already say.

- My first draft of the saved-run notes said nothing for an old file whose snapshot matched the draft. The issue's checklist asks for a line saying the run carries no identity, so that line now always shows.
