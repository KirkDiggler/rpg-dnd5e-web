## Decided

- **An unoriented crossing is held both ways.** An empty `holds_side` (a server before T18), a crossing with neither or both cells in it, and a direction word this client does not know all fail closed — [atlasPath.ts](https://github.com/KirkDiggler/rpg-dnd5e-web/blob/19609cf66cb6006406a11f9da42d98b985f8d657/src/components/session/atlasPath.ts).
- **The walk-into test is per step, not per door.** A hostile `entering` post and a neutral `leaving` post on the same gate leave the leaving steps crossable on the second plan and the entering steps shut on both. S1b's rule, "every holder is neutral or allied", now counts only the holders that bar that step — [atlasPath.test.ts](https://github.com/KirkDiggler/rpg-dnd5e-web/blob/19609cf66cb6006406a11f9da42d98b985f8d657/src/components/session/atlasPath.test.ts).
- **The S1b tests stay as they were, with two edits.** Their `plan` helper passes `holds` in place of the two sets. The exact-set test now names four directed steps, since a hold with no side cells bars both ways — [atlasPath.test.ts](https://github.com/KirkDiggler/rpg-dnd5e-web/blob/19609cf66cb6006406a11f9da42d98b985f8d657/src/components/session/atlasPath.test.ts).
- **A state field the codec does not read is carried, not refused.** This reverses #1384's one refusal of an unknown state field, at the operator's request: a document the server serves must import. A transition stays exact, and a `holds` field is carried the same way — [creatureStates.ts](https://github.com/KirkDiggler/rpg-dnd5e-web/blob/513512be12326b62f0e419942178ad3b903937b5/src/concepts/world-building/creatureStates.ts).
- **The file travels with the draft as a token, not by room id.** Every castle fixture's room is `room-1`, so a registry by room id spliced one document onto another's file. The token is the text's own hash, so the same bytes read twice are still the same draft. It lives in memory only: a draft restored after a reload writes the canonical encoding, which still carries every field the draft holds — [singleRoomDungeon.ts](https://github.com/KirkDiggler/rpg-dnd5e-web/blob/513512be12326b62f0e419942178ad3b903937b5/src/concepts/world-building/singleRoomDungeon.ts).
- **Round 1 set unknown keys aside during the file's decode; round 2 carries them in the draft instead.** The set-aside mode is removed — [strictShape.ts](https://github.com/KirkDiggler/rpg-dnd5e-web/blob/513512be12326b62f0e419942178ad3b903937b5/src/concepts/world-building/strictShape.ts).
- **A few refusals stay, each for a reason.** A retired word is refused by name. A known word its version gate forbids is refused, such as a region `wallFinish` before scene 6. A value the engine would refuse is refused, and so is an asset the renderer cannot draw. The studio's own workspace format stays exact — [CONTRACT.md](https://github.com/KirkDiggler/rpg-dnd5e-web/blob/513512be12326b62f0e419942178ad3b903937b5/src/concepts/world-building/CONTRACT.md).
- **Two kinds live in the file alone.** A play-contract field and a key on a region's cell row are kept by the splice while that part is unchanged. The draft has no place for them: the play contract is fixed, and rows are rebuilt from cells — [singleRoomDungeon.ts](https://github.com/KirkDiggler/rpg-dnd5e-web/blob/513512be12326b62f0e419942178ad3b903937b5/src/concepts/world-building/singleRoomDungeon.ts), [regionRuns.ts](https://github.com/KirkDiggler/rpg-dnd5e-web/blob/513512be12326b62f0e419942178ad3b903937b5/src/concepts/world-building/regionRuns.ts).
- **A misspelt entry word is now named by the server, not the studio.** The "did you mean" hint for an entry key is gone with the refusal; a trigger's hint stays — [answerTableShape.ts](https://github.com/KirkDiggler/rpg-dnd5e-web/blob/513512be12326b62f0e419942178ad3b903937b5/src/concepts/world-building/answerTableShape.ts).

## Found

- **A crossing walked twice needs a third region in the fixture.** The S1b gate fixture has one courtyard, so no walk crosses the opening twice. The S1c fixture walls the cell inside the first crossing off from the rest of the courtyard. The only walk from that cell to the other inside cell goes out by one crossing and back in by the other — [atlasPath.test.ts](https://github.com/KirkDiggler/rpg-dnd5e-web/blob/19609cf66cb6006406a11f9da42d98b985f8d657/src/components/session/atlasPath.test.ts).
- **The preview is only as live as the sighting.** A viewer with the pass gets no `holds_door` from the server, so the gate plans open for that viewer. The web computes nothing about the pass — [design R6](https://github.com/KirkDiggler/rpg-project/blob/main/ideas/the-guard-holds-the-gate/design.md).
- **The direction tests catch mutants.** Swapping the `entering` and `leaving` branches fails seven tests. Opening an unoriented crossing fails eight — [atlasPath.ts](https://github.com/KirkDiggler/rpg-dnd5e-web/blob/19609cf66cb6006406a11f9da42d98b985f8d657/src/components/session/atlasPath.ts).
- **#1384's codec rewrote transition key order.** It wrote `do` before `reason` whatever the author wrote, so gate-1's `heard` transition could not round-trip exactly. Transitions now keep the author's order — [creatureStates.ts](https://github.com/KirkDiggler/rpg-dnd5e-web/blob/513512be12326b62f0e419942178ad3b903937b5/src/concepts/world-building/creatureStates.ts).
- **Unknown-field refusals were not only in the shared allowlist.** Table rows, options, approaches, bundles, cells, selectors and `heard` bodies each had their own loop. A probe that inserts a key at sixteen levels found three still refusing, and it is now a test — [answerTableShape.ts](https://github.com/KirkDiggler/rpg-dnd5e-web/blob/513512be12326b62f0e419942178ad3b903937b5/src/concepts/world-building/answerTableShape.ts).
- **A block collection's range runs past its last newline.** The first splicer inserted one line late and joined lines on replacement. Every end position now steps back over trailing whitespace — [yamlSplice.ts](https://github.com/KirkDiggler/rpg-dnd5e-web/blob/513512be12326b62f0e419942178ad3b903937b5/src/concepts/world-building/yamlSplice.ts).
- **Carrying in the draft made the edit helpers a hazard.** `normalizeBinding`, `normalizeDoorBinding`, `normalizePropBinding`, `normalizeOption` and `setDoorBindingState` rebuilt objects from the keys they know. The splice would then delete a carried field on the first edit. A test that edits through each caught it, and they carry now — [monsterOrderEdits.ts](https://github.com/KirkDiggler/rpg-dnd5e-web/blob/513512be12326b62f0e419942178ad3b903937b5/src/concepts/world-building/monsterOrderEdits.ts).
- **The round-1 splicer aligned list items by index.** A middle delete gave each later item its successor's values while it kept its own unread keys and comments, and the file still parsed. The reviewer's probe on the placements caught it. A mutant that pairs by index now fails six tests — [yamlSplice.test.ts](https://github.com/KirkDiggler/rpg-dnd5e-web/blob/b71cbdee76cce4757014c531db33a0cc3d1cddd6/src/concepts/world-building/yamlSplice.test.ts).
- **An empty value, `b:`, was replaced against its colon** and wrote `b:3`, which does not parse. A zero-width value now gains its space — [yamlSplice.ts](https://github.com/KirkDiggler/rpg-dnd5e-web/blob/b71cbdee76cce4757014c531db33a0cc3d1cddd6/src/concepts/world-building/yamlSplice.ts).
- **An edit inside an anchored map changed its aliases too.** Each untouched alias is now written out as the value it had — [yamlSplice.ts](https://github.com/KirkDiggler/rpg-dnd5e-web/blob/b71cbdee76cce4757014c531db33a0cc3d1cddd6/src/concepts/world-building/yamlSplice.ts).
- **An insert and a removal in one flow row met at one byte** and garbled it (`{say: Let me think.nd5e:…`), found by the say-cue round trip after alignment. A flow map that gains and loses keys is now rewritten whole, and the splicer refuses any two edits that meet instead of writing them — [yamlSplice.ts](https://github.com/KirkDiggler/rpg-dnd5e-web/blob/7d135ddd8eebdff115df1715dc6672044a73ae87/src/concepts/world-building/yamlSplice.ts).
