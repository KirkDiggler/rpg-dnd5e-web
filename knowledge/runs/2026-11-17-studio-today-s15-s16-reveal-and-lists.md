## Shipped

- One reveal contract (`useReveal.ts`, `reveal.tsx`): an item registers under a key `{kind, id, part?}`; a reveal opens what hides it (its own `onReveal`), scrolls it within its own scroll container, focuses the item itself and names it, and marks it until the author's next act — [rpg-project#983](https://github.com/KirkDiggler/rpg-project/issues/983).
- Every studio jump resolves through the one path map to a reveal key (`revealKey.ts`), so it lands on the line, row, post, faction, record, secret, ending, conversation, bundle, behaviour or join it names — [rpg-project#983](https://github.com/KirkDiggler/rpg-project/issues/983).
- `placeName(path, document)` names a place in the file in words; every visible path is now words with the raw path as its title — [rpg-project#983](https://github.com/KirkDiggler/rpg-project/issues/983).
- One list-and-detail piece (`StudioListDetail`): two panes in the workspace height, each scrolling on its own; compact rows (name · one line of summary, small links); rows revealable and a jump to a row chooses it; Up/Down move, Enter/Right go to the detail; below 52rem the panes stack and choosing a row reveals the detail. Threads, Behaviours, Secrets and Cast use it — [rpg-project#984](https://github.com/KirkDiggler/rpg-project/issues/984).

## Decided

- A key's `part` is the rest of the file path after the thing (`options[1].failure[0].recognize`), so items register by the same path the engine and the server write and a jump's key always agrees with an item's — [rpg-project#983](https://github.com/KirkDiggler/rpg-project/issues/983).
- A key nothing has registered yet (a screen the jump opened, still mounting) waits up to 700 ms for its item; meanwhile the reveal has already landed on the closest registered link, and marks nothing when no link is registered — [rpg-project#983](https://github.com/KirkDiggler/rpg-project/issues/983).
- The scroll is the container's own (`scrollTo` on the nearest `overflow: auto|scroll` ancestor); only an item with no such ancestor uses `scrollIntoView({block: 'nearest'})` — [rpg-project#983](https://github.com/KirkDiggler/rpg-project/issues/983).
- A statement's place inside the selection itself (its line, its row) is now a link too, because it reveals that place in the form below; while stale the place is text, as before — [rpg-project#983](https://github.com/KirkDiggler/rpg-project/issues/983).
- A jump to a creature or prop centres the Layout on it at the current zoom; it does not test whether the thing was already in view, because the Layout surface exposes no visible-bounds query to the workspace — [rpg-project#983](https://github.com/KirkDiggler/rpg-project/issues/983).
- The work is split: reveal, jumps and place names here; the list-and-detail piece in the next PR on top, so each is reviewable — [lead's brief](https://github.com/KirkDiggler/rpg-project/issues/983).
- Bundles, Records, Sides (factions and dispositions) and Conversations stay long forms of inline-edited cards: each card already is its own detail, so they get reveal registration only and no list piece — [rpg-project#984](https://github.com/KirkDiggler/rpg-project/issues/984).
- A jump to a list row chooses the row (the piece's `onReveal`), so a jump into Threads, Behaviours, Secrets or Cast lands with the detail shown, not only the row marked — [rpg-project#984](https://github.com/KirkDiggler/rpg-project/issues/984).
- The mark lasts: `data-revealed="true"` stays until the next jump or a click or key press outside the item, never a timer; it is an outline inside the whole row block plus an accent tint, with a short entrance pulse that reduced motion drops — [rpg-project#983](https://github.com/KirkDiggler/rpg-project/issues/983).
- The piece takes its height from its container, never the viewport: the Encounter home is a flex column (tab bars `flex: none`, the group and its panel `flex: 1; min-height: 0`), a list-and-detail section (`data-layout="list-detail"` on the panel: Cast, Secrets, Threads, Behaviours) fills the panel and only its two panes scroll; every other section scrolls as one pane in the same panel. The piece keeps a 10rem floor so a very short window still shows both panes — [rpg-dnd5e-web#1445 review](https://github.com/KirkDiggler/rpg-dnd5e-web/pull/1445#pullrequestreview-5924589431).
- Choosing a row by hand marks nothing (the chosen row shows the choice; the mark is for jumps); stacked, the detail is scrolled into view after it renders. The list is one Tab stop (roving tabindex); Up/Down/Home/End move and choose; Enter/Right go into the detail; Escape, or Left on the detail itself, return; a row's secondary links stay in the Tab order after the focused row — [rpg-dnd5e-web#1445 review](https://github.com/KirkDiggler/rpg-dnd5e-web/pull/1445#pullrequestreview-5924589431).
- One mechanism for every jump: the rows' old refusal-only scroll (`focusRow`, `scrollIntoView` centre) and the `focused`/`focusEnding` openers are retired; a collapsed row, a bundle's route editor and an ending open through their `onReveal`, so a refusal's jump and a read-back's land the same way — [rpg-dnd5e-web#1444 review](https://github.com/KirkDiggler/rpg-dnd5e-web/pull/1444#pullrequestreview-5924775316).
- The revealed item itself takes focus (`tabindex="-1"` when it has none), never a field inside it, and is named from its key by `placeName`; the mark is its focus treatment — [rpg-dnd5e-web#1444 review](https://github.com/KirkDiggler/rpg-dnd5e-web/pull/1444#pullrequestreview-5924775316).
- A reveal lands at once on the closest registered link (a field-level part like `.check` on its row or line) and a closer key registering within 700 ms takes over; the workspace queues a jump's reveal and fires it after the navigation commits, never on a clock — [rpg-dnd5e-web#1444 review](https://github.com/KirkDiggler/rpg-dnd5e-web/pull/1444#pullrequestreview-5924775316).
- One parser for the dialect's paths (`locatePath.ts`): `targetOfPath`, `keyOfPath` and `placeName` all read a path through `locate`; extension steps are in the reveal module's header and `CONTRACT.md` — [rpg-dnd5e-web#1444 review](https://github.com/KirkDiggler/rpg-dnd5e-web/pull/1444#pullrequestreview-5924775316).
- Every place shown in words carries `CopyPath`, a keyboard-reachable "Copy path" control (clipboard, or the path selected in a popover) besides its `title` — [rpg-dnd5e-web#1444 review](https://github.com/KirkDiggler/rpg-dnd5e-web/pull/1444#pullrequestreview-5924775316).
- Copy path is quiet beside a focusable place (`CopyPathGroup`): shown on hover or focus of its place, and the next Tab stop only while the place has focus, so a creature's dozens of places add no Tab stops; beside an unfocusable place it stays a plain button. A jump to a list row focuses the row's own button (`data-reveal-focus`), so Up and Down work at once; a plain container is named as a `role="group"`, a control keeps its own name; "Open cast member" is a jump like the rest — [rpg-dnd5e-web#1444 closure](https://github.com/KirkDiggler/rpg-dnd5e-web/pull/1444#pullrequestreview-5925923735).
