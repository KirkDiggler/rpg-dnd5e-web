# Run — 2026-11-19 — watch a run S3: stopping a watch frees the seat

Slice [rpg-project#1008](https://github.com/KirkDiggler/rpg-project/issues/1008) of story [rpg-project#1003](https://github.com/KirkDiggler/rpg-project/issues/1003). A fix to the shipped watch (S1, S2). Base: `rpg-dnd5e-web` `dev` at [`b250fd01`](https://github.com/KirkDiggler/rpg-dnd5e-web/commit/b250fd01). Branch `watch-leave-s3`.

## Shipped

All in [commit 771affce](https://github.com/KirkDiggler/rpg-dnd5e-web/commit/771affce0e65fac4659fb3ad7f479649019e6fee).

- **Ending a watch leaves the run.** Stop watching calls the game's own Leave (`useSessionLeave` → `SessionService.Exit`) with the watched run's session and member, and only then clears the watch (`watchLeave.ts`).
  - A refused leave shows the server's sentence and a **Stop watching anyway** button, which keeps the run open.
  - A run that is already gone (NotFound) or already ended ("encounter closed") counts as left.
- **A second Watch a run** leaves the first run before it starts the next.
- **Leaving the studio while watching** leaves the run. The leave confirmation says so. If the leave is refused, the confirmation shows the refusal and offers "Leave anyway, the run stays open".
- **Play in the game and the game's Back to the studio do not leave the run.** The run is still being played.
- **A seated character gets the lobby flow's abandon notice.**
  - A watch launch refused because the character is seated elsewhere goes through `useSeatedElsewhere.noteRefusal`, and the studio shows `SeatNotice` under the header. The raw refusal is not repeated in the Save and Play panel.
  - Abandon run relaunches the watch once. A second refusal is shown as the launch's own error, as `LobbyFlow` does.
  - A seat that `GetSeat` reports when the studio opens shows the same notice before any launch, and Watch a run waits until it is abandoned.
- **A reload while watching returns to the studio.**
  - The tab remembers the watched run per player in sessionStorage (`watchMemory.ts`): its session, member and draft.
  - On load, if resume-after-refresh finds that same run, App opens the studio watching it, and the record replays from the start, as after Back to the studio.
  - If the studio's open draft is not the one the run was started from, Home says "The run you were watching is still open", with Resume.
  - Any run not started by a watch resumes exactly as before.
- **The launch hook keeps the raw failure** (`usePlayAuthoredDungeon.failure`) next to its sentence, so a caller can read the refusal's code.

## Decided

- **Leaving the studio leaves the run; the hop to the game does not.** "Back" from the studio is the operator saying they are done, and the studio unmounts for the hop as well, so leaving on unmount would break Play in the game → Back to the studio. Leaving is bound to the two explicit acts (Stop watching, Leave Encounter Studio), never to unmount — [rpg-project#1008](https://github.com/KirkDiggler/rpg-project/issues/1008).
- **The game's Back to Home after a hop does not leave the run.** That is the game's own path, and it never Exits an ordinary run either. The tab keeps the watch mark, so a later reload of that still-open run returns to the studio, not the game.
- **A refused leave stops nothing on its own.** The operator chooses Stop watching anyway, knowing the character stays seated. Silently dropping the watch would hide the seat that S3 exists to free.
- **A seat known at mount disables Watch a run.** This avoids creating a lobby that would only be refused (see Found).
- **sessionStorage, keyed by player.** Another tab never watched the run. Another sign-in in the same tab does not inherit the mark.

## Found

- **Exit by the only member closes the run** (verified by reading, not run). rpg-toolkit `encounter.Exit`: "The encounter auto-closes with the reserved ending "abandoned" if the last member exits and no declared ending has fired". `session.Manager.Exit` then clears the departing player's seat (`write.go`, the "A departing PLAYER gives up its seat" block). A studio launch is a solo lobby of the host's own character, so after Stop watching:
  - the seat is free;
  - the session record stays, CLOSED, until its 24h TTL;
  - the lobby record stays STARTED until its 24h TTL;
  - the player index still points at that lobby, but `GetMyActiveLobby` checks `Status.Open`, finds the run closed, and returns nothing to resume.
- **A refused launch still leaves a WAITING lobby.** `usePlayAuthoredDungeon` runs CreateLobby → SetReady → StartEncounter, and only StartEncounter checks the seat.
  - The web has no call that removes that lobby. `LeaveLobby` exists on the server (pre-start only; it clears the player index) but nothing in `src` calls it.
  - The mount-time `GetSeat` avoids the common case, since Watch a run is disabled while a known seat is shown. A seat taken after the studio opened (for example, in another tab) still costs one orphaned WAITING lobby until its TTL.
  - Abandon then relaunch creates a fresh lobby, so the player index ends on the started one.
  - Using `LeaveLobby` on a refused launch is a candidate follow-up. It would touch World Builder's Play as well.
- **Play (not Watch) still shows a seat refusal as a dead end** in the studio. Only the watch launch routes it to the notice in this slice.
