## Decided

- "Only creatures that changed" now also counts a role's state change, and a sight that came or went. The legend says so — [b7fdfa3c](https://github.com/KirkDiggler/rpg-dnd5e-web/commit/b7fdfa3c).
- `changed` and `knowledge_changed` are not changes of sight. They make no "what happened" line and no timeline mark. They appear only in the creature's "This step" text ("saw X change", "its view of doors or objects changed") — [b7fdfa3c](https://github.com/KirkDiggler/rpg-dnd5e-web/commit/b7fdfa3c).
- A `sighted` beat without `observer` comes from before rpg-project#1001, so the fold ignores it. Old captures and saved runs fold exactly as before — [b7fdfa3c](https://github.com/KirkDiggler/rpg-dnd5e-web/commit/b7fdfa3c).
- A role that a `role_state` beat speaks for is left out of the body's decision-derived label (used before any `state` beat), so it is not said twice. A creature with only `role_state` beats has no body state, and its label is the role alone — [b7fdfa3c](https://github.com/KirkDiggler/rpg-dnd5e-web/commit/b7fdfa3c).
- Saved-run format: no version bump. Fields are saved verbatim, so the new beats replay through the same fold — [b7fdfa3c](https://github.com/KirkDiggler/rpg-dnd5e-web/commit/b7fdfa3c).

## Found

- `sighted` carries direction. Per `sightedbeat.go`, `gained` is first contact or back in view (the beat merges the two), `lost` means left view, `changed` lists visible members whose own state the engine declared changed, and `knowledge_changed` means the view of props or doors changed. The hand-off's example line has only `changed`, so it is not a sighting — [rpg-project#1016](https://github.com/KirkDiggler/rpg-project/issues/1016).
- `role_state.role` is the behavior instance id. It is the same id that `behavior_decision.outcomes[].id` uses and that is written in a qualified `answered.key` (`behavior/11:investigate/…`), so the role bands line up with the timeline's "(investigate)" did-kinds without a mapping — [rpg-project#1016](https://github.com/KirkDiggler/rpg-project/issues/1016).
- The "sees" set is only complete when the record holds the run's start, because the first pass writes everyone's first contact as `gained`. When the record has aged out, the section says "Sees (from the steps the record still holds)" — [b7fdfa3c](https://github.com/KirkDiggler/rpg-dnd5e-web/commit/b7fdfa3c).
