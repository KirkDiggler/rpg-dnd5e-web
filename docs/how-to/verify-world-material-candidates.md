# Verify a private world-material candidate

The world-material reader consumes the provider's v1 catalog and verifies its
owned image subtree. It does not publish assets, write a generated live catalog,
change a consumer pin, or mark appearance/scale acceptance. A successful read of
a staged candidate is not a runtime release.

## Read and verify

Use the repository's installed dependencies and Node 22. Point both paths at the
same private staged bundle. Never copy licensed images into tracked Web files.

```sh
MATERIAL_CATALOG=/absolute/private/bundle/harness/catalogs/synty-world-materials.json \
MATERIAL_MODELS=/absolute/private/bundle/harness/models/synty \
node --input-type=module <<'JS'
import { readWorldMaterialCatalog } from './scripts/world-material-catalog.mjs';
const result = readWorldMaterialCatalog({
  catalogPath: process.env.MATERIAL_CATALOG,
  modelRoot: process.env.MATERIAL_MODELS,
});
console.log(result.catalogSha256);
console.log(result.materials.map(({ ref, repeatMeters }) => ({ ref, repeatMeters })));
JS
```

The reader refuses unknown fields, duplicate refs, invalid parameters,
non-content-addressed paths, symlinks, missing or undeclared material resources,
hash/size drift, inconsistent shared-image metadata and invalid PNGs. PNGs are
fully decoded with CRC checking; the provider's pixel safeguard applies before
decoding. Other runtime subtrees are not inspected or changed. The returned
records contain only consumer URLs, hashes, dimensions and material parameters.
Physical repeats stay in meters; scene-unit conversion belongs to mapping.

## Adopt and reproduce a production provider pin

From a clean, deliberately selected provider checkout, use:

```sh
RPG_GAME_ASSETS_PATH="$PROVIDER" npm run world-materials:sync
RPG_GAME_ASSETS_PATH="$PROVIDER" npm run world-materials:check
```

This produces `src/generated/worldMaterialCatalog.ts` from the real provider
commit and verified v1 catalog. A provider with no material catalog produces an
explicit null catalog digest and empty records; orphan resources still refuse.
The material-only mode touches only `public/models/synty/world-materials/` and
its generated metadata. It cannot enroll a wall, alter geometry or move another
catalog's pin. Adopt approved surface declarations with the existing
`world-assets:sync` workflow separately.

Normal Studio consumes the committed material records and the world catalog's
explicit surface declarations without a preview flag or HTTP candidate catalog.
A Git pin establishes identity; it does not itself assert a provider branch was
merged. Use reviewed, released pins for a merge-ready consumer.

`assets:sync:pinned` reproduces the material subtree from its own pin, including
pinned absence, and checks the assembled and installed resources against the
catalog in that exact Git object. Ordinary customization/NPC adoption likewise
preserves the separately selected material pin. The explicit `--runtime-assets`
HEAD mirror is not the production packaging path.

Docker packaging enumerates the four generated owners with
`scripts/asset-provider-pins.mjs`, fetches only those exact commits and uses the
pinned runtime union. It does not regenerate tracked catalogs in CI or take
material resources from an unrelated provider HEAD. `ASSETS_READ_TOKEN` remains
required for private binary access.

## Stage an explicit Studio preview

After the ordinary pinned runtime asset sync, stage a verified private bundle
from the Web worktree (Node22's type stripping reads the committed generated
world-asset module):

```sh
node --experimental-strip-types scripts/stage-world-material-preview.mjs \
  --catalog "$BUNDLE/harness/catalogs/synty-world-materials.json" \
  --models "$BUNDLE/harness/models/synty" \
  --world-catalog "$WORLD_CANDIDATE" \
  --runtime-root public/models/synty
```

`$WORLD_CANDIDATE` is the provider's generated surface-catalog fixture, not a
hand-edited enrollment. The stage verifies enrolled GLB hashes against both the
committed Web pin and the installed file. Failure leaves an existing owned stage
unchanged. It refuses to replace an unrelated directory.

Set `VITE_WORLD_MATERIAL_PREVIEW=1` in this worktree's ignored `.env.local` and
start/restart its named local stack from the workspace root. Vite's dev-only
middleware serves `.local/world-material-preview/` at `/world-material-preview/`.
The files live outside `public/`, so a production build does not copy them. No
production catalog/pin is generated by this command.

In Studio, use **Castle Wall Fit 01** for the supported wall appearance. Select a
wall under **Build** and choose **Wall finish (both sides)** in Arrange, then
**Apply Arrange**. **Set sides separately** exposes A/B choices; the map labels A
on the left of Start→End and B on the right. No region is needed, including for
standalone walls or projecting sections. These fields share Apply/Cancel with
staged dimensions and geometry. Clearing a face restores its region/authored
default. Caps and door artwork stay unchanged.

For bulk defaults and shared alignment, **Regions → Room masonry** remains
available on resolved enclosed rooms. Explicit wall choices win over those
defaults. **Pattern start** controls the room's closing seam; unowned wall
intervals use the wall's Start-relative pattern. **N** hides the options panel.
Unknown/incompatible choices remain saved and show an unapplied-finish diagnosis,
never a silently substituted material. Candidate previews remain explicitly labeled.

Region choices/anchors use scene6; per-wall choices opt into scene7. Both survive
the existing local save/history and JSON/YAML paths. This is not Play delivery. Candidate acceptance
and publication remain evidence-bound provider gates; a successful local stage is
not approval. After restaging a candidate, reload Studio to read its new metadata.

## Surface bindings and runtime resource ownership

The world-asset generator accepts optional provider `surfaces` declarations with
exact `id`, `node`, `material`, `side` and `family` fields. Missing declarations
remain absent. A miter capability does not imply material enrollment. Generated
asset types and rows must still be produced through the generator, not edited by
hand.

`src/rendering/worldSurfaceMaterials.ts` is the material-only renderer primitive:

1. Prepare a detached placement hierarchy and its fitted UV chart.
2. Load the selected catalog images as a complete set. Create/cache samplers by
   immutable image identity **and sampling role/channel**, using
   `createWorldSurfaceSampler`; samplers share pixels, not mutable settings.
3. Call `applyWorldSurfaceMaterials` with provider bindings and explicit
   selections. All targets/maps are checked before any material is assigned.
   Exact node/material identity can select multiple exported primitive meshes.
4. In the shared model path, pass loaded selections as `surfaceSelections` to
   `WorldPropModel` / `WorldAssetModel`. Their existing material-treatment owner
   applies the finish before remembered/lighting overlays and restores in reverse
   order on replacement/unmount. It reapplies on StrictMode setup and allocates
   nothing for suspended render attempts. Do not add a second material effect.
   Standalone callers must likewise remove overlays before `dispose()`.

The primitive changes only selected material slots and owns only its material
clones. The caller owns samplers and changed geometry. Restoring/disposal never
frees shared images, cached geometry, or the source model's materials.

This path requires the fitted derivative normal basis: no stale tangents, paired
color/normal UV channels, and identity sampler transforms. Logical normal strength
is multiplied by the authored renderer basis sign, not copied over it. A changed
chart must establish its correct basis before material application; this primitive
does not infer a room chart or prove GPU shading. Missing/incompatible selections
refuse explicitly, not as color-only success or fallback artwork.

The primitive alone adds no Studio selector, room persistence, room-loop mapping
or Play delivery. Those consumers must integrate it through the existing document
and renderer owners.
