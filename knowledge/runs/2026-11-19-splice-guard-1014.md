# Run — 2026-11-19 — the file writer checks its own output

Bug [rpg-project#1014](https://github.com/KirkDiggler/rpg-project/issues/1014), found in the review of [#1459](https://github.com/KirkDiggler/rpg-dnd5e-web/pull/1459#pullrequestreview-5970549824). Base: `rpg-dnd5e-web` `dev` at [`84789fe2`](https://github.com/KirkDiggler/rpg-dnd5e-web/commit/84789fe2). Branch `splice-guard-1014`, PR [#1460](https://github.com/KirkDiggler/rpg-dnd5e-web/pull/1460), with three review rounds ([first](https://github.com/KirkDiggler/rpg-dnd5e-web/pull/1460#pullrequestreview-5971273244), [second](https://github.com/KirkDiggler/rpg-dnd5e-web/pull/1460#pullrequestreview-5976001038), [third](https://github.com/KirkDiggler/rpg-dnd5e-web/pull/1460#pullrequestreview-5976468711)).

## Shipped

- **The guard.**
  - `spliceYaml` (`src/concepts/world-building/yamlSplice.ts`) checks its own text before returning it. The text must read back as the file's value with the edit applied (`checkWrite`).
  - If not, the write throws `UnsafeWriteError`, whose message is the studio's sentence: "The studio could not write this change safely, so nothing was changed." followed by where.
  - Anything that goes wrong while writing or checking is that refusal too. This includes an alias whose anchor the write lost and a writer that throws.
- **The edit is refused at the commit.**
  - Every room edit goes through `commitRoomDocument`. It calls `assertSourceWritable` before keeping the edit.
  - A refusal shows the sentence. The document, the saved draft and undo stay as they were.
  - Export and publish use the same guarded splice.
- **Always the whole text.** The guard parses the entire write and compares it with the intended value. A cheap path that parsed only the edited lines was built and then removed (see Decided and Mistaken).
- **The guard regression test.** It runs seeded castle edits, and faulty writes of each built from the third review's 37 fault kinds plus a BOM line. Every sound write must pass, and a faulty write may pass only if it means the edit. This holds by construction while the guard parses the whole text, and it fails if a shortcut comes back.
- **A row keeps its dash.** When the first key of a block-list row goes, the next key moves up onto the dash line, and the comment above that key goes above the dash. When the row's only key goes, `- {}` is left.
- **Compact lists take every edit.** In a list written `- - 3`, the first row that stays keeps the shared line. A fallback rewrite sets the comments of the rows that stay above the parent row.
- **Emptied collections.** A map or list whose every entry goes is written `{}` or `[]` on its key's line. Before this, an emptied map was written `key:`, which reads as null. `dev` did that silently.
- **New room has no file.** It no longer carries the replaced document's `sourceRef`.
- **The castle probe** walks every list, map and scalar.

## Decided

- **The comparison rule.**
  - Counts: list order, every key, every scalar and its type.
  - Ignored: key order, comments and layout.
  - Because: the engine and the studio read maps by key and lists by position.
  - Known gap: numbers compare as numbers, so `1` and `1.0` are not told apart. The splice never writes that change.
- **No shortcut in the guard.** The guard always parses the whole write.
  - Because: a guard must be sound by construction. A partial parse re-implements YAML's context rules, and three review rounds each found writes it passed that the full parse refuses.
- **The only refusal a commit swallows is the encoder's, before it splices** (a policy form part-way through). Everything after that fails closed.
- **The cost.** These are measurements on the served castle for a keystroke in a policy text field:

  |                                                  | dev    | the cheap-path head | now        |
  | ------------------------------------------------ | ------ | ------------------- | ---------- |
  | commit check                                     | none   | 33 ms               | 86–88 ms   |
  | with the publish panel's encode (the file's key) | 149 ms | 58 ms               | 111–115 ms |
  | the same, with another key                       | 147 ms | 65 ms               | 168–170 ms |
  - The encoder no longer parses its own canonical text again.
  - The common case (the file's key) is under `dev`.
  - Another publish key is about 21 ms slower than `dev`. The commit check writes with the file's key, so when the panel's key differs, the reuse of the checked write misses, and the panel does a second full splice and check.
  - The lead accepted that for this PR. The follow-up is to let the commit check encode with the panel's key.

## Found

- **On `dev`, 33 list writes failed, all in the courtyard's compact paint runs.** Moves inside a run were unparseable, and removing or editing a run's first value gave the wrong value.
- **On `dev`, every emptied block map was written `key:`, which is null.** The first round's guard caught it and refused the edit. That broke New room after an import, and removing the last key of any map. The castle probe walked only lists, so it missed this. It now walks maps and scalars too.
- **On `dev`, removing the first key of a block-list row (`- id: a`) dropped the row's dash.** The file then did not parse, or read differently. The guard found it: 471 key removals across the castle were refused under `SPLICE_PROBE=all`. The writer is now fixed.
- So the guard surfaced two writer bugs that `dev` writes silently: emptied maps and first-key removal.
- **Two writer limits remain, and the guard now correctly refuses both.** Each is a small issue to file:
  - a multi-line string written into a flow row;
  - removing two adjacent keys from a flow map.
- **Another publish key costs about 21 ms more than `dev` per keystroke**, because the reuse misses (see Decided). This is a follow-up.
- **A row whose `id` changes in an id-aligned list is a different row.** It is written where the old one stood, so its list's bytes change. That is by design.

## Mistaken

- **I took "the castle probe passes" to mean the writer was sound.** It walked lists only. Every node kind the studio can edit needs probing.
- **The commit test mocked `spliceYaml` and called the guard itself.** Deleting the guard from `spliceYaml` failed no test. The tests now break the writer below the guard, through `spliceInternals`.
- **The compact fallback dropped the comment that made it fire.** Its test checked only the value.
- **The first short path trusted indentation alone.** YAML context comes from the lines around a part. The second review accepted 7 wrong documents through it:
  - a line written one level too deep;
  - a region that lost its last newline;
  - a list at its key's column rewritten as a map;
  - a line turned into a block scalar header.

  The preconditions and the agreement test came from that review. The third review found three more holes:
  - tabs, no-break spaces and a BOM counted as indentation;
  - `...` and `---` lines read as document markers once a part was dedented;
  - a `key: scalar` line written as a flow map.

  Those holes appeared in 93 of 285 hand-written cases and in 4,432 of 52,167 seeded faulty writes. Three rounds found gaps, so the cheap path was removed. A guard that has to re-derive YAML's rules to stay sound is the wrong shape.

- **The first probe recorded every swap twice.**
